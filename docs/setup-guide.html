2큰 그림: 주소를 입력하면 무슨 일이 일어나나

설정 하나하나를 이해하려면 먼저 사용자의 요청이 지나가는 길을 알아야 합니다. 도메인을 산 뒤의 구조는 아래와 같습니다.

1
주소 조회 (DNS): 브라우저는 crowdview.com 같은 이름을 바로 찾아가지 못합니다. 그래서 DNS에 "이 이름의 서버 IP가 뭐야?"라고 묻습니다. Cloudflare DNS가 "Vercel 서버의 IP야"라고 답합니다.
2
요청 (CDN): 브라우저가 그 IP, 즉 사용자와 가장 가까운 Vercel 엣지 서버로 접속합니다. 여기서 HTTPS 암호화, 방화벽 검사, 캐시 확인이 일어납니다.
3
캐시가 있으면: 엣지 서버가 저장해 둔 페이지를 곧바로 돌려줍니다. 서버 코드는 실행되지 않습니다. 빠르고, 거의 공짜입니다.
4
캐시가 없거나 만료됐으면: Vercel 함수(Next.js 서버 코드)가 실행되어 서울시 API나 Redis에서 데이터를 가져와 페이지를 만듭니다. 이 결과는 다시 캐시에 저장됩니다.
5
예약 작업 (Cron): 사용자 요청과 별개로, 정해진 시각에 Vercel이 데이터 갱신과 비용 리포트 함수를 스스로 호출합니다.
핵심요금은 대부분 ④ 함수 실행과 그 뒤의 외부 서비스 호출에서 나옵니다. 그래서 요금 폭탄을 막는 가장 강력한 방법은 ③에서 끝나는 요청의 비율을 높이는 것, 즉 캐시입니다. 4장에서 다룹니다.

3꼭 알아야 할 기초 개념 9가지

3-1. 도메인과 등록업체(Registrar)

도메인은 crowdview.com 같은 사람이 읽기 쉬운 인터넷 주소입니다. 도메인은 사는 것이 아니라 1년 단위로 빌리는 것이어서 매년 갱신해야 합니다. 갱신을 놓치면 남이 가져갈 수 있으니 자동 갱신을 켜 두세요.

도메인을 빌려주는 회사를 등록업체(Registrar)라고 합니다. 가비아, Cloudflare, AWS Route 53 등이 있습니다.

  • Cloudflare는 도메인을 원가에 팔고 마진을 붙이지 않습니다. .com 기준 연 약 1.5만 원입니다.
  • WHOIS(도메인 주인 정보)도 무료로 비공개 처리해 줍니다.
주의: .kr 도메인Cloudflare는 .kr과 .co.kr을 팔지 않습니다. .kr을 원하면 가비아 같은 국내 업체에서 사고, "네임서버"만 Cloudflare로 바꾸면 됩니다. 결과적으로 DNS 관리는 똑같이 Cloudflare에서 하게 됩니다.

3-2. DNS: 인터넷의 전화번호부

사람 이름(도메인)으로는 전화를 걸 수 없고 전화번호(IP 주소)가 필요합니다. DNS는 이름을 번호로 바꿔 주는 전화번호부입니다. 전화번호부의 한 줄 한 줄을 DNS 레코드라고 부릅니다.
레코드뜻CrowdView에서 쓰는 곳
A이름 → IPv4 주소crowdview.com → Vercel IP
CNAME이름 → 다른 이름 (별명)www → Vercel 주소
TXT아무 글자. 주로 "이 도메인 주인이 맞다"는 증명에 씁니다Resend 메일 발송 인증 (SPF, DKIM)
MX이 도메인의 메일을 받는 서버Resend 반송 메일 처리
NS이 도메인의 전화번호부를 관리하는 곳 (네임서버)Cloudflare (도메인을 사면 자동 설정)

TTL은 "이 답을 몇 초 동안 기억해도 되는지"입니다. DNS를 바꿨는데 바로 반영되지 않는 이유가 여기에 있습니다. 전 세계 DNS 서버가 예전 답을 TTL 동안 기억하기 때문입니다. 보통 몇 분에서 몇 시간이 걸립니다.

3-3. 프록시(주황 구름)와 DNS only(회색 구름): 왜 끄나

Cloudflare에서 DNS 레코드를 추가하면 구름 아이콘이 있습니다.

🟠 Proxied (주황, 기본값)

사용자 요청이 Cloudflare 서버를 먼저 거친 뒤 Vercel로 갑니다. Cloudflare의 캐시와 방화벽이 앞에 붙습니다.

⚪ DNS only (회색)

Cloudflare는 주소만 알려주고 빠집니다. 사용자는 Vercel로 바로 접속합니다.

"보안은 Cloudflare, 호스팅은 Vercel" 조합이 흔해 보이지만, Vercel은 공식 문서에서 Cloudflare 프록시를 앞에 두는 것을 권장하지 않습니다. 이유는 다음과 같습니다.

  • Vercel에 이미 CDN, 방화벽, DDoS 방어가 들어 있습니다. 같은 일을 두 번 하게 되고, 한 번 더 거치는 만큼 느려집니다.
  • Vercel이 진짜 사용자를 못 봅니다. 모든 요청이 Cloudflare IP에서 오는 것처럼 보여서 Vercel 방화벽, 봇 탐지, IP별 속도 제한이 제대로 동작하지 않습니다.
  • 캐시가 두 겹이 됩니다. 한쪽을 지워도 다른 쪽에 옛 페이지가 남아 "배포했는데 왜 안 바뀌지?" 같은 문제가 생깁니다.
  • HTTPS 인증서 충돌로 526, 525 같은 오류가 날 수 있습니다.
  • Vercel 요금이 줄지 않습니다. 4장의 캐시 설정을 하면 Vercel 안에서 같은 효과를 얻습니다.
결론Cloudflare = 도메인 + DNS(회색 구름). 나머지는 Vercel 한 곳에서 관리합니다. 문제가 생겼을 때 볼 곳이 한 군데라서 운영이 단순해집니다.

3-4. HTTPS와 인증서

주소창의 자물쇠는 사용자와 서버 사이의 통신이 암호화되어 있다는 뜻입니다. 암호화하려면 "이 서버가 진짜 crowdview.com이 맞다"는 인증서가 필요합니다.

  • Vercel은 도메인을 연결하면 Let's Encrypt 인증서를 자동으로 발급하고, 자동으로 갱신합니다. 할 일이 없습니다.
  • 프록시를 끄는 이유 중 하나도 이 자동 발급이 방해받지 않게 하려는 것입니다.
  • HTTPS가 아니면 브라우저가 위치 권한 같은 기능을 막습니다.

3-5. CDN과 캐시

본사 창고(서버) 하나에서 전국으로 배송하면 느리고 비쌉니다. 그래서 동네마다 편의점(엣지 서버)을 두고 잘 팔리는 물건(페이지)을 미리 진열해 둡니다. 손님 대부분은 편의점에서 바로 사 가고, 진열대가 비었을 때만 본사에 주문합니다. 이것이 CDN(Content Delivery Network)입니다.

어떤 응답을 얼마나 오래 진열할지는 서버가 Cache-Control 헤더로 알려줍니다. 웹 표준이라 Vercel, CloudFront, Cloudflare 어디서나 같은 뜻입니다.

지시어뜻
public누구에게나 같은 응답이므로 공용 캐시(CDN)에 저장해도 됩니다.
max-age=0브라우저는 저장하지 말고 매번 물어보라는 뜻입니다. 대신 CDN이 가까이에서 빠르게 답합니다.
s-maxage=60CDN은 60초 동안 이 응답을 그대로 재사용합니다. (s = shared)
stale-while-revalidate=30060초가 지난 뒤 5분 동안은 일단 옛 응답을 즉시 주고, 뒤에서 새로 만듭니다. 사용자는 기다리지 않습니다.
private, no-store개인 정보가 담긴 응답이므로 절대 저장하지 않습니다. 로그인 후 내 정보 같은 응답에 씁니다.

ISR(Incremental Static Regeneration)은 Next.js가 페이지 HTML에 이 캐시 방식을 자동으로 적용해 주는 기능입니다. 코드에 export const revalidate = 60 한 줄만 쓰면 됩니다.

3-6. 서버리스 함수와 리전

예전에는 서버 컴퓨터를 24시간 켜 두고 월세를 냈습니다. 서버리스 함수는 요청이 올 때만 코드가 실행되고, 실행된 만큼만 돈을 냅니다.

  • 요청이 0이면 비용도 0이고, 요청이 몰리면 자동으로 여러 개가 동시에 실행됩니다.
  • 반대로 요청이 폭증하면 비용도 그대로 폭증합니다. 이것이 3-9의 요금 폭탄입니다.

리전(Region)은 함수가 실행되는 데이터센터의 위치입니다.

  • 지금은 기본값인 iad1(미국 워싱턴)에서 돌고 있습니다. 한국 사용자 요청과 서울시 API 호출이 태평양을 왕복하는 셈입니다.
  • icn1(서울)으로 바꾸면 응답이 빨라집니다. DB와 Redis도 서울 리전에 만들어 함수와 같은 곳에 두는 것이 원칙입니다.

3-7. Cron (예약 작업)

"매일 09:00에 이 주소를 호출해"처럼 정해진 시각에 자동으로 실행되는 작업입니다. CrowdView는 두 가지를 씁니다.

  • 혼잡도 데이터 미리 갱신 (/api/cron/refresh)
  • 비용 리포트 발송 (/api/cron/cost-report)

무료(Hobby) 플랜은 하루 1회만 허용합니다. Pro로 바꾸면 데이터 갱신을 10분 주기로 돌릴 수 있습니다. 아무나 이 주소를 호출하지 못하도록 CRON_SECRET이라는 비밀번호를 헤더로 확인합니다.

3-8. 환경변수와 비밀값

API 키나 비밀번호를 코드에 직접 쓰면, 코드가 GitHub에 올라가는 순간 유출됩니다. 그래서 환경변수로 따로 보관하고 코드는 process.env.이름으로 읽기만 합니다.

보관 장소용도
.env.local내 컴퓨터에서 개발할 때 씁니다. .gitignore에 들어 있어 GitHub에 올라가지 않습니다.
Vercel 환경변수 (Sensitive)운영 서버에서 씁니다. 저장한 뒤에는 대시보드에서도 값을 다시 볼 수 없습니다.
.env.example어떤 변수가 필요한지 이름만 적어 둔 견본입니다. 값은 넣지 않습니다.
원칙키는 채팅, 메신저, 스크린샷에 붙여 넣지 않습니다. 특히 NCP 계정 키는 모든 권한을 가진 마스터 키라서 유출되면 남이 내 카드로 서버를 마음대로 만들 수 있습니다.

3-9. 사용량 과금과 "요금 폭탄"

클라우드 요금은 대부분 쓴 만큼 나옵니다. 축제 기간에 방문자가 100배로 늘면 비용도 100배가 될 수 있습니다. 이를 막는 방법은 세 겹으로 생각합니다.

겹방법CrowdView 적용

대가 (트레이드오프)

  • 화면의 혼잡도가 최대 1분 정도 늦을 수 있습니다. 원본인 서울시 데이터 자체가 5~15분 단위로 갱신되기 때문에 사용자가 느끼는 차이는 거의 없습니다.
  • "n분 전 갱신" 표시도 최대 1분 차이가 납니다.
  • 나중에 로그인한 사용자별 화면(즐겨찾기 등)을 만들면 그 부분은 private로 따로 처리해야 합니다. 남의 정보가 캐시되면 안 되기 때문입니다.

잘 되는지 확인하는 법

curl -sI https://crowdview-three.vercel.app/api/crowd | findstr /i "cache"

cache-control: public, max-age=0
x-vercel-cache: MISS     ← 첫 요청: 함수가 실행됨
(다시 실행하면)
x-vercel-cache: HIT      ← CDN이 바로 응답, 함수 실행 없음
x-vercel-cache: STALE    ← 만료된 응답을 주면서 뒤에서 갱신 중

Vercel은 s-maxage를 CDN에서만 쓰고 브라우저로 보내는 응답에서는 지웁니다. 그래서 위처럼 max-age=0만 보이는 것이 정상입니다.

5단계별 할 일과 그 이유

0단계: 지금 바로 (무료)

1
직접서울시 일반 인증키 발급: data.seoul.go.kr → 인증키 신청 → 일반 인증키. 받은 키를 .env.local에 SEOUL_OPENAPI_KEY=키값으로 넣습니다.

지금 화면의 혼잡도는 예측 모델 값입니다. 이 키가 있어야 서울시가 통신 데이터로 집계한 실제 혼잡도를 보여줄 수 있습니다. 공공데이터포털(data.go.kr) 키와는 다른 키입니다.

2
직접관광지 집중률 API 활용신청: data.go.kr에서 "한국관광공사_관광지 집중률 방문자 추이 예측 정보"를 신청합니다.

서울 밖 관광지(에버랜드 등)의 30일 혼잡 예측을 무료로 받을 수 있습니다. 이미 가진 data.go.kr 키로 쓸 수 있습니다.

3
직접비용 리포트 수신 확인: 매일 09:00에 PDF가 왔는지 확인합니다.

무료 플랜은 로그를 1시간만 보관해서 Claude가 나중에 성공 여부를 확인할 수 없습니다.

4
직접중복 프로젝트 crowd-view 정리 여부 결정

같은 저장소에 연결된 Vercel 프로젝트가 두 개라서 커밋할 때마다 두 번 배포됩니다. 삭제는 되돌릴 수 없으니 직접 결정해 주세요.

5
Claude서울시 키 등록·검증, 함수 리전을 서울(icn1)로 변경

키는 운영 환경변수에 등록해야 운영 서버가 쓸 수 있고, 리전은 3-6에서 설명한 속도 문제 때문에 바꿉니다.

1단계: 도메인 구입 (Cloudflare)

1
직접dash.cloudflare.com에 가입하고, Domain Registration → Register Domains에서 이름을 검색해 결제합니다. 자동 갱신도 켭니다.

vercel.app 주소는 신뢰도가 낮고 바꿀 수 없습니다. 내 도메인이 있어야 브랜드, 메일 발송, 나중의 클라우드 이전까지 주소를 유지할 수 있습니다. 도메인은 호스팅을 옮겨도 그대로 가져갑니다.

2단계: 도메인을 Vercel에 연결

1
직접Vercel → crowdview → Settings → Domains → Add에서 도메인과 www를 추가합니다.

Vercel에 "이 도메인으로 오는 요청은 이 프로젝트로 보내라"고 알려주는 단계입니다.

2
직접Vercel이 보여주는 A/CNAME 값을 Cloudflare → DNS → Records에 입력하고, Proxy status를 DNS only(회색)로 바꿉니다.

3-2의 전화번호부에 "이 이름 = Vercel"이라고 적는 단계입니다. 회색 구름인 이유는 3-3에서 설명했습니다.

3
직접Vercel 화면에 Valid Configuration ✓가 뜰 때까지 기다립니다.

DNS 변경이 퍼지고(3-2의 TTL), Vercel이 HTTPS 인증서를 발급하는 시간(3-4)입니다.

3단계: 도메인 연결 후

1
직접NCP 콘솔 → Maps → Application → Web 서비스 URL에 새 도메인을 추가합니다.

네이버 지도 키는 등록된 주소에서만 동작합니다. 남이 내 키를 훔쳐 써서 내 요금이 나가는 것을 막는 장치입니다.

2
직접Resend → Domains → Add Domain을 하고, 안내된 TXT/MX 레코드를 Cloudflare에 추가합니다.

지금은 Resend 테스트 주소에서 발송하기 때문에 가입한 이메일로만 보낼 수 있습니다. 도메인을 인증하면 report@내도메인으로 누구에게나 보낼 수 있고, 스팸함에 빠질 확률도 줄어듭니다.

4단계: 기능 개발 중 (필요할 때)

1
직접Vercel → Storage → Create Database에서 Supabase와 Upstash Redis를 만듭니다. 둘 다 Free 플랜, Seoul 리전입니다.

Supabase(DB)는 로그인과 즐겨찾기 저장에 씁니다. Redis는 여러 서버 함수가 함께 쓰는 공용 캐시입니다. 지금은 함수마다 따로 메모리에 캐시해서 서로 공유되지 않습니다. Vercel에서 만들면 접속 정보가 환경변수로 자동 입력됩니다.

5단계: 출시 직전 (결제를 켜는 날)

1
직접사업자등록과 통신판매업 신고

토스페이먼츠 같은 결제대행사(PG)는 사업자 계약이 원칙이고, 온라인으로 유료 구독을 팔려면 통신판매업 신고가 필요합니다.

2

Hobby는 비상업용 약관입니다. 결제를 받는 순간 Pro가 필요합니다. Pro는 10분 주기 Cron, 긴 로그 보관, 지출 한도 기능을 제공합니다.

3
직접Spend Management: 한도 약 $100, 50/75/100% 알림. 자동 일시정지는 넉넉한 금액으로 설정합니다.

3-9의 세 번째 겹입니다. 일시정지 금액을 너무 낮게 잡으면 축제 피크, 즉 사용자가 가장 많을 때 사이트가 꺼집니다. 캐시가 1차 방어선이므로 정지선은 진짜 사고에 대비한 최후 수단으로 둡니다.

4
직접외부 서비스 예산 상한: Upstash, 네이버 클라우드 예산 알림, Claude API 지출 한도

Vercel 한도는 Vercel 요금만 지켜줍니다. 각 서비스의 요금은 각자 설정해야 합니다.

5
Claude방화벽 속도 제한(/api/*), 지출 알림을 디스코드로 연결, Cron 10분 주기, 결제 연동, 리포트에 Vercel 사용량 추가

3-9의 두 번째 겹(막기)과, 매일 받는 리포트에서 비용을 한눈에 보기 위한 작업입니다.

6SA 관점: 나중에 직접 클라우드로 옮길 때

Vercel은 아래 표의 왼쪽 열을 버튼 몇 번으로 대신 해주는 서비스입니다. 직접 클라우드로 옮긴다는 것은 오른쪽 열을 하나씩 직접 설계하고 연결한다는 뜻입니다. 지금 Vercel에서 각 기능이 무슨 문제를 푸는지 이해해 두면, 나중에 같은 문제를 AWS나 GCP 부품으로 푸는 것이 SA의 일이 됩니다.

지금부터 지키는 이식성 원칙

  • 표준을 먼저 씁니다. 이번 캐시 설정은 Vercel 전용 기능이 아니라 HTTP 표준 Cache-Control 헤더로 했습니다. CloudFront로 옮겨도 그대로 동작합니다.
  • 설정은 환경변수로 둡니다. 키나 주소를 코드에 박지 않았기 때문에, 옮길 때 Secrets Manager에 같은 이름으로 넣으면 됩니다.
  • 도메인은 호스팅과 분리합니다. 도메인을 Vercel이 아니라 Cloudflare에서 사는 이유가 이것입니다. 나중에 DNS 레코드 몇 줄만 바꾸면 이사가 끝납니다.
  • Vercel 전용 부분은 기록해 둡니다. 이전할 때 손볼 곳은 아래와 같습니다.
Vercel 의존 지점옮길 때 할 일
vercel.json의 cronsEventBridge Scheduler가 같은 주소를 Authorization: Bearer CRON_SECRET 헤더와 함께 호출하도록 만듭니다.
ISR (revalidate)자체 호스팅하면 Next.js 캐시 저장소를 S3나 Redis로 지정해야 합니다. OpenNext가 이 작업을 해 줍니다.
after() 백그라운드 갱신Lambda는 응답 후 실행이 보장되지 않습니다. OpenNext 설정을 확인하거나 큐(SQS)로 분리합니다.
Git 연동 자동 배포, 미리보기 URLGitHub Actions와 IaC(Terraform 또는 CDK)로 직접 구성합니다. SA 포트폴리오로도 좋은 소재입니다.
언제 옮기나 (판단 기준)사용자 1,000명 규모까지는 Vercel의 월 $20이 직접 운영하는 시간보다 쌉니다. 다음 중 하나에 해당하면 이전을 검토합니다.
  • Vercel 청구액이 꾸준히 $100 이상 나올 때
  • Vercel이 제공하지 않는 기능(VPC 내부 DB, 장시간 작업 등)이 필요할 때
  • 학습과 포트폴리오 목적으로 같은 구조를 AWS에 IaC로 재현해 보고 싶을 때. 이 경우 운영은 Vercel에 두고 스테이징을 AWS에 따로 만드는 방법도 있습니다.

도메인
사람이 읽는 인터넷 주소입니다. 1년 단위로 빌립니다.

도메인을 빌려주는 회사입니다. Cloudflare, 가비아 등이 있습니다.
DNS
도메인을 IP 주소로 바꿔주는 인터넷 전화번호부입니다.
네임서버 (NS)
특정 도메인의 DNS 레코드를 관리하는 서버입니다.
A / CNAME 레코드
각각 이름 → IP, 이름 → 다른 이름을 뜻합니다.
TTL
DNS 답이나 캐시를 기억해도 되는 시간(초)입니다.
프록시
요청을 중간에서 받아 대신 전달하는 서버입니다. Cloudflare의 주황 구름이 프록시입니다.
HTTPS / TLS
암호화된 통신입니다. 인증서가 필요합니다.
CDN / 엣지
사용자 가까이에 둔 캐시 서버망입니다. 엣지는 그 개별 서버를 말합니다.
Cache-Control
응답을 어디에 얼마나 저장할지 알려주는 HTTP 헤더입니다.
s-maxage
CDN 같은 공용 캐시의 보관 시간입니다.
stale-while-revalidate
만료된 응답을 먼저 주고 뒤에서 갱신하는 방식입니다.
ISR
Next.js가 페이지를 정해진 주기마다 다시 만들어 CDN에 두는 방식입니다.
캐시 HIT / MISS / STALE
각각 캐시에서 응답, 캐시가 없어 서버 실행, 만료된 캐시로 응답하면서 갱신 중이라는 뜻입니다.
서버리스 함수
요청이 올 때만 실행되고 실행량만큼 과금되는 서버 코드입니다.
리전
코드나 데이터가 위치한 데이터센터의 지역입니다. 서울은 icn1(Vercel), ap-northeast-2(AWS)입니다.
Cron
정해진 시각에 자동으로 실행되는 예약 작업입니다.
환경변수
코드 밖에 보관하는 설정값과 비밀값입니다.
레이트리밋

DDoS
대량의 요청으로 서비스를 마비시키는 공격입니다.
Spend Management

IaC
Infrastructure as Code. 인프라를 코드(Terraform, CDK)로 정의하고 재현하는 방식입니다.
OpenNext
Next.js 앱을 Vercel이 아닌 AWS 등에 배포할 수 있게 해 주는 오픈소스입니다.
PG
결제대행사입니다. 토스페이먼츠 등이 있습니다.
