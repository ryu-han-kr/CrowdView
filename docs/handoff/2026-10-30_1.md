## 2. SK '지금 실제 인원' — 원인과 현재 상태

- **원인**
  - SK 퍼즐 장소 혼잡도는 **정해진 장소 약 3만 4천 곳만** 지원한다.
  - TMAP 검색에서 나온 첫 번호가 이 목록에 없으면 `NOT_FOUND_POI`로 거절된다(예: 남산서울타워 → 퍼즐에는 'N서울타워'로 등록).
- **수정**
  - `scripts/korea-data/skt-pois.mts`로 지원 목록(API가 앞 3만 곳까지만 줌)과 우리 장소를 이름으로 맞췄다. 결과는 `src/data/skt-pois.json`이고 **242곳 중 99곳**이 지원된다.
  - 지원되는 곳은 이 번호로 바로 조회한다. 지원하지 않는 곳은 SK를 부르지 않고 "이 장소는 아직 실제 인원 데이터가 없어요"라고 안내하며, 횟수도 차감하지 않는다.
  - 이름이 달라 손으로 맞춘 곳: namsan→N서울타워, lotteworld→롯데월드어드벤쳐, high1→하이원리조트스키장, phoenix→휘닉스평창스노우파크 등(`MANUAL`).
- **확인됨**: 경복궁에서 'SK텔레콤 실측 · 원활'이 나오는 것을 경수님 캡처로 확인했다.
- **SK 응답 원문**: `{"datetime":"2026103003000","congestion":3.79292E-5,"congestionLevel":1}`
  - congestion은 **㎡당 추정 방문자 수**(SK 문서 기준: 추정 방문자 수 ÷ 연면적)다.
- **경수님 결정 대기**
  1. 지원하지 않는 143곳에서 **버튼을 숨길지**
  2. 요금 안내에 '일부 장소' 표시를 넣을지

## 3. 진행 중 — 실제 인원을 '몇 명'으로 (경수님 10/30 요청, 내일 이어서)

- **요청**: 단계(원활 등) 말고 **몇 명**인지 보여 주고, **SKT·KT·LG U+·알뜰폰 비율(%)**로 나눠 보여 주기.
- **계산 방법**: 인원 = congestion(㎡당) × 장소 넓이(㎡). SK는 넓이를 주지 않는다.
  - `scripts/korea-data/skt-areas.mts`가 OpenStreetMap 경계로 넓이를 잰다(Overpass, 장소 1.5km 안 같은 이름 중 가장 넓은 도형). 결과는 `src/data/skt-areas.json`.
  - **10/30 새벽에 99곳을 측정했다.** 브랜치 `feat/live-headcount`에 있고 커밋은 하지 않았다. 내일 결과를 검토할 것: 너무 크거나 작은 값, 건물 하나만 잡힌 곳.
  - 예: 경복궁 약 43만㎡이면 새벽 3시 3.79e-5 × 432,703 ≈ 16명이다.
- **통신사 비율**: 휴대폰 회선 점유율(과기정통부 2026년 2월) — SKT 39.00% · KT 23.30% · LG U+ 19.58% · 알뜰폰 18.09%.
  - SK 문서와 기사에 따르면 SK 추정 방문자 수는 **SKT 가입자 데이터를 이미 전체 인구로 환산한 값**이다. 그래서 N명이 전체이고, 통신사 비율은 'N명을 점유율로 나눈 참고값'으로 보여 주는 게 정직하다. 장소별 실제 통신사 비율이 아니라는 점을 화면에 적을 것.
  - 이 해석(이미 전체 환산인지)은 SK 문의(skopenapi@sktelecom.com)로 확인하는 게 가장 확실하다.
- **내일 할 일**
  1. 넓이 검토
  2. `live-count`/`skt.ts`가 congestion 수치를 함께 반환
  3. 버튼 결과 카드에 '약 N명' + 통신사 비율 막대 + 출처 문구
  4. 전후 사진을 보여 드리고 머지

## 4. 사진 고르기 — 경수님 기준과 절차 (메모리 `photo-curation-process`)

- **절차**: ① 사전조사(Claude 웹 검색으로 유명 명소·포토 스폿) → ② 명소별로 쓸 수 있는 사진 수집(위키미디어 공용 CC, 관광공사) → ③ 기준 채점 → ④ **애매한 건 경수님 확인**
- **기준**
  - 사진만 봐도 어떤 곳인지 보일 것
  - 색감이 좋고 해상도가 높을 것
  - 인스타 감성일 것
  - 대표 명소(에버랜드라면 장미원·사파리·판다·퍼레이드·놀이기구)가 담길 것
  - 전경도 좋고, 한두 가지만 강조한 사진도 좋다
  - **야경은 야경으로 유명한 곳만**, 대표 사진은 낮 사진 우선
  - 참고 예시: 아고다 여행 가이드 사진
- **도구**: `scripts/korea-data/photo-pick.mts`
  - 기본 모델 Sonnet 5.5
  - `APPROVE=everland:1,3`이면 확인 시트에서 고른 번호를 photos로 옮긴다
- **에버랜드 2차 시험 결과**: 운영에는 반영하지 않았다.
  - 백업 위치: 스크래치 `photo-picks-everland-trial.json`. 다시 돌려도 된다(약 150원).
  - 판다 클로즈업이 대표(10점), T익스프레스·장미원 등 12장이 채택, 애매 5장이다.
  - **경수님 확인 대기**: 대표 사진(판다 vs 기존 전경), 확인 시트 번호.
  - 기준이 바뀌었으니(야경) 다시 돌린 뒤 보여 드릴 것.
- **저작권**: 위키미디어 공용에는 화려한 퍼레이드·야경 사진이 적다. 공식 홍보 사진, 언론 사진, 인스타 사진은 쓰면 안 된다. 정말 좋은 사진은 각 장소 홍보팀에 사용 허락을 받는 게 확실하다(경수님 메일).
- **관광공사 관광사진 갤러리 API가 10/30 현재 모든 검색어에 0건**을 돌려준다(경복궁도 0). 키나 활용신청 상태를 확인할 것.
