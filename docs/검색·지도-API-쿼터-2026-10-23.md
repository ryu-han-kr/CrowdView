# 검색·지도 API 쿼터 점검 (2026-10-23)

카카오맵 무료 쿼터, Brave Search 사용량이 많은 이유, Tavily 사용량을 정리했어요. 숫자는 2026-10-23에 공식 문서와 운영 Redis 집계(`quota:*`)에서 확인했어요.

## 1. 카카오맵 API (지도·로컬)

### 무료 쿼터는 어떻게 주나
- **개발자 계정 기준으로 처음 카카오맵을 켠 앱 하나에만** 무료 쿼터를 줘요. 그 앱에는 [카카오맵 무료 쿼터] 뱃지가 붙어요. 우리 앱(카카오 로그인 앱)이 처음 켠 앱이라 무료 대상이에요.
- 다른 앱에서 카카오맵을 또 켜면 그 앱은 무료 쿼터 없이 쓴 만큼 바로 과금돼요. 비즈월렛을 연결해야 쓸 수 있어요. **새 앱에서는 켜지 마세요.**
- 무료 양을 다 쓰면 429 오류가 나요. 유료 설정을 하면 넘는 양부터 과금돼요.

### 무료 양과 넘으면 내는 요금 (공식 쿼터 문서)
| API | 하루 무료 | 넘으면 |
|---|---|---|
| 지도 Web(JavaScript) SDK | 300,000건 | 0.1원/건 |
| 키워드로 장소 검색 | 100,000건 | 2원/건 |
| 카테고리로 장소 검색 | 100,000건 | 2원/건 |
| 주소→좌표, 좌표→주소, 좌표→행정구역, 좌표계 변환 | 각 100,000건 | 0.5원/건 |
| 정적 지도 | 1,000건 | 2원/건 |

- 월간 쿼터는 전체 API를 합쳐 3,000,000건이에요.
- 일간 쿼터와 요금은 카카오가 나중에 바꿀 수 있다고 적어 두었어요.

### 우리 사이트가 쓰는 양
우리는 **키워드로 장소 검색**(`lib/kakao-local`) 하나만 써요. 지도는 네이버 지도라 카카오 지도 SDK는 안 써요.

| 쓰는 곳 | 1회에 부르는 수 | 저장 |
|---|---|---|
| 코스 추천 '가고 싶은 곳' 검색 (`/api/route/search`) | 검색어 1개당 1건. 입력을 멈춘 뒤 0.25초 지나야 부르므로 검색 한 번에 보통 3~5건 | 같은 검색어·위치(약 100m)는 24시간 |
| 코스 만들기: 애니·백화점·플래그십 관심사 (`getKakaoCandidates`) | 고른 관심사마다 2~3건, 셋 다 고르면 7건 | 같은 출발지(약 100m)는 24시간 |
| 상태 확인 (`/api/health` keyProbe) | 배포마다 30분에 1건 | — |

- 추정: 하루 코스 100번에 검색 200번이면 약 1,700건이에요. 무료 10만 건의 2%도 안 돼요. 1만 명이 하루 한 번씩 써도 무료 안이에요.
- 오늘부터 호출 수를 `quota:{날짜}:kakao-local`로 세요. 운영 리포트와 `/api/health`의 `quotaHot`에 나와요. 90%(9만 건)에 닿으면 그날은 우리 자료만으로 동작해요.
- **주의:** 카카오 데브톡 답변에 따르면 같은 정보를 미리 일괄로 불러 DB에 쌓아 두는 방식은 정책상 금지예요. 우리는 사용자가 요청할 때만 부르고 결과는 24시간 캐시만 해요(DB 저장 없음). 캐시 기간이 문제가 되면 1시간으로 줄이면 돼요.

## 2. Brave Search: 왜 많이 썼나

### 숫자
- 운영 집계로 10/22에 45건, 10/23에 45건을 썼어요(이번 달 누적 90건). 우리가 정한 하루 한도 60건의 75%라 "70% 넘게 사용"으로 보였어요.
- 집계에 안 잡힌 호출이 따로 있었어요. `/api/health`의 키 확인(keyProbe)이 **배포마다, 그리고 30분마다** Brave 1건과 Tavily 1크레딧을 썼어요. 10/22에 배포가 열 번 넘게 있었고 점검 요청도 많아서, Brave 대시보드 숫자가 우리 집계보다 커요.

### 원인
1. **요즘 뜨는 곳 뉴스 갱신(하루 1번):** 장소 28곳(테마파크·워터파크·거리·명소·해변)마다 1건, 테마파크 17곳은 "○○ 이벤트" 검색을 1건 더 해서 매일 45건이에요. 11~3월에는 스키장 9곳이 더해져 54건이 돼요.
2. **키 확인:** 위에서 말한 집계 밖 호출이에요.

### 요금 확인
- Brave는 2026년 2월부터 새로 가입한 계정에 무료 플랜 대신 매달 $5 크레딧을 줘요. 약 1,000건이고, 1,000건당 $5예요. 카드 등록이 필요하고, 넘으면 상한 없이 과금돼요.
- 우리 키는 10/22에 받았으니 이 방식일 가능성이 커요. 그런데 예전 설정(월 2,000건)대로 매일 45건씩 쓰면 한 달에 약 1,400건이라 **약 $2가 과금될 수 있었어요.**
- Brave 대시보드에서 플랜 이름과 남은 크레딧을 한 번 확인해 주세요. 예전 무료 플랜(월 2,000건)이라면 `BRAVE_MONTHLY_LIMIT` 환경변수로 다시 올리면 돼요.
- **확인됨 (10/23, 사용자):** 대시보드 기준 Search 월 1,000회, Answers 월 1,000회. 우리 한도(하루 30·월 900)가 Search 1,000회 안이라 그대로 둬요. Answers는 쓰지 않아요.

### 고친 것 (이 커밋)
| 항목 | 전 | 후 |
|---|---|---|
| 뉴스 갱신 | 매일 28곳 전부 (45건) | 날마다 절반씩 번갈아, 장소마다 이틀에 한 번 (약 23건, 스키 시즌 약 27건). 차례가 아닌 곳은 저장된 소식(3일)을 그대로 씀 |
| 하루 / 월 한도 | 60 / 2,000 | 30 / 900. 90%에서 멈추고 Tavily로 대신 |
| 키 확인 (Brave·Tavily) | 배포마다·30분마다, 집계 밖 | 하루 1번, 집계에 포함 |

- 예상 사용량은 한 달 약 700~830건이라 $5 크레딧(1,000건) 안이에요.

## 3. Tavily
- 무료(Researcher) 플랜은 월 1,000크레딧이에요. 우리 한도는 하루 30, 월 1,000이에요.
- Brave가 실패하거나 한도에 닿을 때만 써요. 운영 집계상 이번 달 사용은 0이에요(키 확인 호출은 빼고). 키 확인도 이제 하루 1번만 하고 집계에 들어가요.

## 4. 과금 막기 (2026-10-23 추가)

### 카카오 로컬
- 앱 한도를 **하루 2만 건·월 50만 건**(무료 하루 10만·월 300만의 1/5)으로 낮췄어요. 90%(하루 1.8만)에 닿으면 그날은 카카오를 부르지 않고 우리 자료만 써요. `KAKAO_DAILY_LIMIT`·`KAKAO_MONTHLY_LIMIT`로 바꿀 수 있어요.
- 카카오가 429(쿼터 초과)를 주면 그날 남은 호출을 막아요.
- 상태 확인(keyProbe)은 배포마다·30분마다가 아니라 **하루 1번**만 부르고 집계에 넣어요. 배포를 여러 번 해도 늘지 않아요.
- 카카오 콘솔: **[유료 설정]을 켜지 않고 비즈월렛을 연결하지 않으면** 무료 양을 넘어도 429만 나고 돈은 안 나가요. 다른 앱에서 카카오맵을 켜지 마세요(그 앱은 처음부터 유료).

### Sentry (han-2m/crowdview, Developer 무료 플랜)
- 무료 플랜은 한도(오류 월 5천 건 등)를 넘으면 **버려질 뿐 과금되지 않아요.** Pay-as-you-go 예산을 켜지 마세요.
- DSN(Client Key) 자체에 **하루 150건** 상한을 걸었어요(월 5천 ÷ 30일).
- 코드: 운영(production)에서만 켜져요. 미리보기 배포·CI·로컬은 보내지 않아요. 성능 추적 1%, 오류 리플레이 10%, 한 화면에서 오류는 많아야 5건.
- 빌드 때 소스맵 업로드는 하지 않아요(`withSentryConfig` 없음) → 배포마다 쓰는 양은 0이에요.
