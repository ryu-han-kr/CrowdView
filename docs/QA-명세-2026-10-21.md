## 3. 자동화 고려점 (CrowdView에 맞춘 것)

1. **시험 도구는 지금 것 유지**: 단위는 Node 기본 `node:test`(이미 44개, 추가 설치 없음), 화면은 Playwright(휴대폰 크롬·사파리 엔진·PC). 명세의 Vitest·fast-check는 같은 내용을 반복문 검사로 대신했다(예: 0~100 모든 점수, 인원 0~8,000 단조 증가).
2. **CI에는 비밀 키가 없다** → 공공데이터 대신 예측 값이 나온다. 그래서 **개수·숫자 대신 장소 id·주소·문구**로 확인한다. 운영 확인은 `E2E_BASE_URL=https://crowdview.app npm run e2e`(읽기 전용).
3. **시간 고정**: 서버 시간은 화면 시험에서 고정할 수 없다 → 날짜 판단은 `festivalStatus(f, today)`처럼 **오늘을 인자로 받는 함수**로 만들고 단위 시험한다. 브라우저 쪽은 Playwright `page.clock`으로 고정할 수 있다.
4. **ISR 캐시가 날짜 버그의 원인**(홈 5분, 축제 1시간): 날짜로 갈리는 표시는 브라우저에서 다시 계산하거나 캐시 시간을 짧게.
5. **외부 장애 재현**: 브라우저 요청은 `page.route`로 막는다(EXP-S02처럼). 서버 쪽 공공데이터는 `dataGoKr()` 한 곳을 지나므로 **고정 자료 모드**(예: `DATA_FIXTURES=tests/fixtures`)를 넣으면 Normal·Stale·Empty·Invalid·Timeout을 재현할 수 있다 → 📋 다음 단계.
6. **지도는 캔버스** → 마커에 `data-place-id`를 달아야 목록↔마커 비교가 된다 → 📋.
7. **결제는 토스 테스트 키 + 심사용 계정**, 운영 실결제 금지. 중복 승인처럼 DB가 필요한 시험은 테스트 DB(Neon 브랜치)에서.
8. **실기기 몫**: 위치 권한 팝업, 지도 손가락 조작, 웹 푸시, 홈 화면 앱(PWA).
9. **운영 감시**(읽기 전용): 서울 자료 신선도(기준 시각이 90분 넘은 비율), 공공 API 오류율 — `/api/cron` 기록과 오류 알림(하루 30건 제한)으로 이미 일부.
