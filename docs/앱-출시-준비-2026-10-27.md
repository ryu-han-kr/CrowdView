# 앱 출시 준비 (2026-10-27)

경수님 10/27: "모바일 앱으로도 출시. UI·데이터는 이미 있으니". → **웹사이트를 그대로 앱 껍데기에 담는 방식**으로 간다(화면·자료를 따로 만들지 않음, 고치면 앱도 바로 바뀜).

## 1. 방식

| | 안드로이드 (먼저) | 아이폰 (나중) |
|---|---|---|
| 방식 | TWA: 앱 안에서 크롬이 사이트를 주소창 없이 띄움 | 웹뷰 앱(Capacitor 등) |
| 만드는 도구 | PWABuilder(pwabuilder.com, 웹에서 앱 파일 생성) — 컴퓨터에 안드로이드 개발 도구 설치 불필요 | **맥(Mac)이 꼭 필요** (Xcode). 없으면 클라우드 빌드(Codemagic 등) |
| 등록비 | 구글 플레이 개발자 $25 (한 번) | 애플 개발자 $99 / 년 |
| 로그인 | 크롬이라 구글·카카오 로그인 그대로 | 웹뷰에서 구글 로그인이 막힘 → 바깥 브라우저로 로그인 처리 필요 |
| 심사 위험 | 낮음 | **4.2 '웹사이트 포장만 한 앱' 반려** 위험 → 푸시 알림·즐겨찾기 위젯 같은 앱 기능을 붙여야 함 |

## 2. 걸리는 것 (문제 될 수 있는 것)

1. **Plus 결제**: 앱 안에서 디지털 구독을 팔면 구글은 Play 결제(또는 한국 '사용자 선택 결제'), 애플은 인앱 결제가 원칙(수수료 15~30%). 토스 결제를 앱 안에서 그대로 쓰면 반려될 수 있음.
   → 선택지: (가) 앱에서는 Plus 구매 버튼을 숨기고 웹에서만 판매, (나) Play 결제 연동(Digital Goods API). **경수님 결정 필요**
2. **개인정보처리방침·데이터 보안 양식**: 플레이 콘솔에 개인정보처리방침 주소(사이트에 있음)와 '수집하는 데이터' 설문 작성.
3. **위치 권한**: 지도 '내 위치'는 웹 권한 그대로 동작(TWA).
4. **푸시 알림**: 안드로이드 TWA는 웹 푸시가 그대로 됨. 아이폰은 앱 쪽 푸시(APNs) 연동이 따로 필요.
5. **광고**: 앱 안 애드센스는 웹 화면이라 그대로 나오지만, 구글 정책상 앱에는 AdMob이 원칙 → 앱에서는 광고를 끄는 것이 안전(나중에 결정).

## 3. 이번에 사이트에 해 둔 것 (PR 앱 준비 1단계)
- 앱 아이콘(가장자리까지 채운 maskable 아이콘) `public/icon-maskable.png`
- 매니페스트: id·scope·세로 고정·언어·분류·바로가기(지도·공항)
- `/.well-known/assetlinks.json`: 안드로이드 앱이 이 사이트 소유자 앱임을 증명. 환경변수 `ANDROID_CERT_SHA256`(앱 서명 지문)을 넣으면 채워짐. 패키지 이름 기본값 `app.crowdview.twa`
